# API contracts

The executable contract is the OpenAPI document generated by FastAPI:

- Interactive Swagger UI: `/docs`
- OpenAPI JSON: `/openapi.json`
- Stable prefix: `/api/v1`

All non-health requests require `Authorization: Bearer <token>`. Mutating tool
requests require a stable idempotency key. Errors always use:

```json
{
  "code": "machine_readable_code",
  "message": "Safe user-facing detail",
  "request_id": "correlation-id"
}
```

## Main resources

| Area | Endpoints |
| --- | --- |
| Authentication | `GET /api/v1/auth/me` |
| AI Agent | `POST /api/v1/chat` |
| Agent Assist | `POST /api/v1/agent-assist` |
| Conversations | `GET/POST /api/v1/conversations`, `GET /api/v1/conversations/{id}` |
| Support tools | `POST /api/v1/conversations/{id}/tools/{tool}` |
| Approvals | `GET /api/v1/approvals`, `POST /api/v1/approvals/{id}/decision` |
| Escalation | `POST /api/v1/conversations/{id}/escalate` |
| Tickets | `GET/POST /api/v1/tickets`, `PATCH /api/v1/tickets/{id}/assignment` |
| Knowledge | `GET/POST /api/v1/knowledge-sources` |
| Analytics | `POST /api/v1/analyses`, `GET /api/v1/analyses/{id}` |
| Evaluations | `POST /api/v1/evals/run` |
| Admin | `GET /api/v1/admin/dashboard`, `GET /api/v1/admin/audit-events` |
| Agent versions | `GET/POST /api/v1/admin/agent-versions` |
| Health | `GET /health/live`, `GET /health/ready` |

Pydantic request and response definitions are in `supportsense/models.py`.
Role checks and resource visibility are tested in `tests/test_rbac_isolation.py`.

Creating an agent version with `active: true` promotes it for that tenant and
deactivates the previously active version. Runtime chat uses the active
version's rollout stage, capped by the deployment-wide rollout stage. The
`customer_visible` response field is enforced server-side: customer callers do
not receive internal drafts, citations, confidence, or tool details during
offline, shadow, or Agent Assist operation.
